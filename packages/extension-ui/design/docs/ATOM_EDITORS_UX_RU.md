# StatePort / StateAtom — UX v2

## Что изменилось

Визуальный эталон — HTML-прототип. Сохранены его оболочка, знак StatePort, палитра, типографическая иерархия и контекст приложения. Тексты, объяснявшие концепцию, заменены значениями, источниками, контролами и короткими статусами. В Figma создана отдельная страница v2; старые экраны оставлены в Archive · UX v1.

### Редактирование на первом экране

Выбранное свойство и выражение располагаются над редакторами входов. В строках видны Received → Draft, точка изменения, переключатель либо поле и сброс строки. Нет обязательного перехода в мастер эксперимента.

Boolean переключается явно true/false. Число и строка вводятся в поле. Enum использует заданную в демо схему; продукт не должен придумывать допустимые значения по имени поля. Объект/массив редактируются через JSON; в Fields массив имеет встроенное поле JSON. У поля через меню доступны Edit in JSON, Reset original, Set null, Remove field. Удаление и null — разные операции.

### Один редактор ответа, один draft

Edit full response открывает Fields / JSON / Changes. Они изменяют одну модель данных. HTTP status и Delay относятся к тому же draft. Некорректный JSON сохраняется в редакторе, показывает ошибку и блокирует Apply. Изменение отдельного поля отражается в JSON; изменение JSON отражается в полях. Changes сравнивает draft с исходным ответом.

Fields не заменяет полноценный редактор схем. Неизвестные ключи, добавление новых полей и замена корневого типа доступны через JSON. Подмена применяется только к выбранной синтетической цели; редактор произвольного request matcher не реализован в этом UX-прототипе.

### Переменные и вычисляемые результаты

Local state содержит formValid, а Other component inputs — props-подобное variant. Оба являются явно поддержанными синтетическими writable-адаптерами. disabled — вычисляемое read-only свойство, а не произвольно перезаписываемая переменная.

В настоящем движке для каждого такого контрола нужен контракт: место записи, допустимый тип, поддерживаемая операция, область применения и способ обновления/восстановления. Наличие значения в памяти само по себе не означает возможности его безопасно редактировать.

### Честный цикл применения

1. Original: исходные данные доставлены.
2. Prepared: создан draft; приложение ещё не изменилось.
3. Apply: при первом применении — область и разрешение. По умолчанию повторяется безопасное чтение демо-данных.
4. Waiting for request: правило включено, ответ ещё не доставлен. Для проверки этого состояния отключить Repeat safe read after Apply.
5. Applied: данные доставлены; приложение пересчитало свойство.
6. Remove rules отключает правила, но не отменяет уже доставленные данные. До повторного чтения показывается Not restored.
7. Restore & reload удаляет правила и выполняет повторное получение исходных данных.

Результат — краткий diff наблюдаемого состояния, а не автоматически сформулированная причина бага. Закрытие панели не скрывает активную подмену: остаётся индикатор с Restore.

### Без IDE, PM и production

Browser only позволяет вручную редактировать ответы без IDE. Поля обозначены как кандидаты, выражение и недоступные связи с кодом не рисуются. Unknown source также не запрещает ручную подмену.

Summary — факты и reporter input, не генератор интерпретаций. Production остаётся read-only даже при переключении в Technical. Экспорт brief бесплатный и работает; он не является воспроизводимой State Card. Continue in StatePort — только предварительный handoff без ложного сообщения о сохранении.

Маскирование экспорта в прототипе демонстрирует интерфейс на синтетических данных. Это не проверенная универсальная защита от секретов. Перед настоящим sharing нужны отдельные redaction policy, review и тесты безопасности.

## Где брать содержимое без LLM

| UI | Источник в продуктовой реализации |
|---|---|
| Имя свойства, имя поля, тип, исходное значение | Выбранный DOM/adapter target, захват данных, типовая схема |
| Выражение и location | Результат анализатора доступных исходников |
| Стрелка между входом и ответом | Provenance/evidence edge с идентификатором конкретного обмена |
| Доступность записи и контрол | Writable capability адаптера и тип данных |
| Prepared / Waiting / Applied / Not restored | Состояние draft, правил и фактической доставки |
| Результат эксперимента | Сравнение наблюдаемого свойства до/после |
| Ожидаемое поведение | Пользовательский ввод |

В прототипе все эти источники заменены явно заданными fixtures. Ни один динамический абзац не требует вызова модели.

## Что проверить руками

- Credit hold: переключить creditHold на false → Apply → Allow & apply → увидеть доступную Confirm → Restore & reload.
- Two blockers: убрать один блокер, затем второй; отсутствие эффекта первой подмены не называется отсутствием зависимости.
- Edit full response: Fields → изменить значение → JSON → убедиться в том же draft → Changes.
- В JSON ввести невалидное содержимое; проверить блокировку Apply и сохранение draft после закрытия/открытия.
- Через меню поля установить null, удалить, восстановить.
- Numbers & strings: изменить total/currency; после Apply меняется итог в приложении.
- Browser only: редактирование API доступно без подключения кода.
- Scope: отключить auto-read; проверить Waiting, затем Refresh data.
- Applied → Remove rules: приложение остаётся с доставленной подменой до Restore.

- 65 браузерных проверок: значения, draft/delivery, ручной API без IDE, статусы, задержка, ошибки JSON, массивы, null/remove/reset, writable state/props, два блокера, read-only, export, клавиатура и отображение на 1440×960, 1280×800, 1024×768 и 390×844.

## Границы готовности

Это интерактивная UX-симуляция, не установленное расширение, не анализатор кода и не реальный перехватчик HTTP. IDE, source maps, runtime adapters и подтверждённые связи здесь демонстрационные. Не проверены произвольные сайты, реальные корпоративные профили, взаимодействие настоящих расширений, потоковые HTTP-ответы, Chrome permissions и реальное восстановление состояния приложения. Основной StatePort и автономный технический эксперимент не изменены.
