# StatePort Extension · UX v3

## Что это

Расширение существующего UX-прототипа v2: Capture, отдельная страница настроек, профили доменов, source maps и Action Inspector. Визуальный эталон — HTML v2; белые поверхности, синяя акцентная палитра, компактные значения и непосредственные редакторы сохранены. Это не установленное Chrome-расширение, не готовый анализатор и не результаты технического эксперимента StateAtom.

Весь интерактивный просмотр — `StatePort_extension_v3.html`. Открыть локально в браузере. Исходники — `source/`. Верхняя тёмная полоса управляет демонстрацией; она не входит в проектируемое расширение.

Figma: https://www.figma.com/design/PdAC6xFCNtGHdzStethUbW?node-id=28-2
Новая страница: `StatePort · v3 · Capture & Settings` (23:2). 18 экранов/состояний и обзорная рамка. 538 нативных текстовых слоёв, векторные элементы и прототипные переходы. v2 и архив v1 сохранены. Figma показывает ключевые фиксированные состояния; полноценные редакторы, проверки и переходы состояния реализованы в HTML.

## 1. Capture

Путь: Capture → Start Capture & Reload → Recording → Stop and Review → Desktop Review → выбор работы с browser sign-in → simulated durable receipt → Saved.

Перенесены существующие смыслы, а не придуман новый capture engine:
- Desktop подключён отдельно от IDE. `Ready for Chrome` не равно `Chrome connected`.
- Основной старт перезагружает вкладку после готовности записи. Альтернатива без перезагрузки явно помечена частичной.
- Additional API origins: по одному точному origin на строку, настройка до захвата.
- Закрытие панели не останавливает запись: Stop/Discard остаются в плавающих контролах страницы.
- Stop не означает Saved. Review и решение про browser sign-in находятся на стороне Desktop.
- Saved не означает Verified. Демонстрационный receipt подписан; настоящая State Card не создаётся.
- Прерывание отладки не вызывает автоматического переподключения/перезагрузки. Сохраняется частичный материал для Review.
- Scope/limits показаны как сведения о текущем capture, а не тумблеры для неподдерживаемого захвата всей памяти, storage, кода или streaming replay.

В прототипе Desktop Review — имитация handoff, не предложение переносить весь Review в расширение. Кнопка явно называется `Simulate Desktop save`.

Новая UX-политика, а не утверждение об уже существующем коде: Capture просит сначала восстановить активные подмены Atom, чтобы не смешивать базовые и экспериментальные условия незаметно.

## 2. Настройки

Отдельная расширенная поверхность через шестерёнку, не маленький popup. Разделы: Domains, Capture, Source maps, Listeners & hooks, Local explanation, Connections.

Для доменных настроек профиль идентифицируется `scheme://host:port`. Настройки staging, production и localhost не наследуются друг от друга. Выбор профиля настроек не переключает исследуемую вкладку. Дополнительные API origins и origin сервера source maps — разные разрешения и поля.

Профиль хранится локально. Если браузер запрещает localStorage, работает явный session fallback. Ни cookies, ни токены, ни пароли в настройки этого прототипа не записываются. Несохранённый draft не является применённой конфигурацией; Save/Discard доступны отдельно. Это прототип редактора, не готовая система enterprise policy.

### Source maps

Три способа: Automatic / Internal URL / Local files (.map или ZIP). Для внутреннего URL отдельно предоставляется разрешение на origin сервера. Оно не выдаёт корпоративные права и не обходит SSO.

Различаются две оси:
1. Идентичность сборки: Exact match / Unverified / Build mismatch / Not checked.
2. Содержимое: Source available / Positions only / Not available.

При mismatch связи не применяются. Совпадения имени файла недостаточно для Exact. Наличие source map не повышает статический путь до статуса наблюдавшегося исполнения. Карты и исходники не добавляются автоматически в brief, облако или модель.

`Check demo build` использует контролируемые fixture-условия, раскрываемые в Demo build conditions. Выбор `.map`/ZIP в HTML читает имя файла, а НЕ парсит карты и НЕ скачивает артефакты. Check не выполняет сетевого запроса. Эти элементы демонстрируют UX, а не фактическую проверку production-сборки.

## 3. Слушатели, handlers и hooks

Восстановленные решения соседнего обсуждения учтены как следующие разные поверхности:
- **Handlers**: прикладные click/change/submit-обработчики, имя функции, исходник, компонент/регистрация.
- **Native listeners**: target, phase, native versus delegated root dispatcher; покрытие может быть частичным.
- **Hooks**: владеющий компонент и его экземпляр. Hooks не названы слушателями DOM. `useEffect` без доказанной связи с действием остаётся `Component only`.
- **Trace preview**: будущий отдельный UX-сценарий. Статический путь не объявляется исполненным. Observe само по себе не вызывает обработчик.

Показанные функции, файлы и вызовы — синтетический пример. Никакого перехвата настоящих callback, monkey patching функций или заказа POST не выполняется. Вызов в прототипе появляется только после отдельного демонстрационного события. Для disabled Confirm он не регистрируется. Сбор аргументов выключен; его последующее включение не дописывает значения в уже записанные вызовы.

Глубокая Action Trace не считается частью уже готового narrow technical scope. Она визуально и в заметках отделена как будущая стадия; полный текст соседней спецификации не подменяется этими макетами.

## 4. Необязательное локальное объяснение

Соседний разговор включал отдельный этап Local AI. Поэтому в настройках есть `Local explanation`, по умолчанию off. Состояния демонстрации: unavailable / downloadable / downloading / available. Без него инспекция, подмены и экспорт продолжают работать. Нет облачного fallback и дополнительной авторизации модели.

Кнопка Explain simply показывается только после включения доступной локальной возможности. Её демонстрационный результат подписан `Template preview · not model output`. Прототип не скачивает и не запускает модель. В продуктовом контракте это производное изложение установленных фактов, не механизм получения evidence или установления причин.

## 5. Что сохранено из Atom v2

Непосредственные редакторы входов, статусы draft/waiting/applied/restored, единая подмена между Fields/JSON/Changes, валидация JSON, status/delay, source-chain и бесплатный brief. Ручная подмена API без IDE не заблокирована подключением Capture/Settings.

## 6. Проверки

Команды из корня комплекта:

```sh
python source/build_standalone.py
node --test tests/extension-model.test.cjs
node --test source/tests/v2-engine.test.cjs
python tests/browser.py
python tests/local-explanation.py
```

Среда: Python Playwright и `/usr/bin/chromium`. При другом расположении Chromium измените `executable_path` в двух скриптах. В проверенной среде Browser connector не получил originating context, а file navigation заблокирована администратором. Политики не менялись: HTML отрисовывался через Playwright `set_content`. Поэтому реальная постоянная запись настроек при запуске файла не заявляется проверенной; session fallback проверен.

Результаты: 21 тест новой модели + 20 регрессионных тестов Atom v2; 52 проверки браузерных сценариев + 4 проверки Local explanation. Размеры 1440×1000, 1280×800, 390×844. JavaScript-ошибок и внешних HTTP-запросов в прогоне нет. Это не проверка CDP/native messaging, source-map parser, модели или реального расширения.

Figma визуально проверена на Capture, source-map Settings и Hooks. Исправлены переносы бейджей, выравнивание значений, видимость контролов и выбранное состояние Local files. HTML остаётся спецификацией полной интерактивности. В Figma есть небольшие типографические отличия (Roboto Mono вместо системного monospace), несколько сокращённых подписей и не все прокручиваемые части/ошибки представлены отдельными кадрами; пиксельная идентичность всей страницы не заявляется.

## Основания и границы изменений

Текущий capture workflow сверялся с `apps/chrome-extension/README.md` и `src/popup.html` репозитория `redvoron/scenariodeck`, commit `9a0c4b612b046eea624b8ccf0dcc6dd01eb569a1`. Source Mapping — по предоставленному соседнему обсуждению: три режима, sourcesContent, идентичность сборки, локальная приватность. Handlers/hooks/Local AI — по найденным фрагментам истории; полный файл `STATEATOM_ACTION_INSPECTOR_LOCAL_AI.md` не был доступен. Остальное — предложенные и явно демонстрационные UX-состояния.

Производственный репозиторий StatePort и работающий технический эксперимент не изменялись. Никакие плагины пользователю не устанавливались, реальные аккаунты, сайты и рабочие браузерные профили не использовались.
