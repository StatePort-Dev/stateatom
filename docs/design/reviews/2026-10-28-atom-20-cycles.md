# Atom UX — 20 review/fix cycles

User authorization: 2026-10-28, up to eight hours, autonomous implementation with
20 successive designer/product reviews and fixes. Start: 17:02 UTC; time limit:
2026-10-29 01:02 UTC. This is a time budget, not a promise of human acceptance.

## Acceptance frame

1. Select one element and immediately understand what was recorded about its inputs.
2. Change supported page/response values without rediscovering hidden configuration.
3. See the real page effect, know whether a change applied or is waiting, and undo.
4. Reach exact code when a source location is available.
5. Keep technical details available without giving them equal visual priority.

Use the preserved extension-ui reference, existing tokens and actual runtime
capabilities. Do not fake writable recorded reads, source links, causal relations,
production permission, or live values. Generic page fields remain explicitly separate
from proven dependencies. English UI follows the current source/reference language.

Each cycle records: fresh before capture, designer review, product review, fix,
after capture, behavior/keyboard/narrow check and remaining limits. A passing
scenario is not evidence for unsupported adapters or arbitrary state mutation.
