## What the source implementation does

`core/inspection-explanations.mjs` projects a frozen schema2 local presentation
record with exact tab/frame/run/build/page/instance/observation/source-generation/
inspection/root identity, referenced existing evidence IDs, concise fixed summaries,
next action and local details. It neither creates graph edges nor app observations.

A selected property requires the current source-validated target, matching native
selection/marker instance, source digest/range and complete retained target closure.
Boolean read operands require the exact source span, available scope and particular
structural parent dependency. A transitive earlier same-span value behind another
operand, independent observation, foreign source/page/scope or stale report cannot
fill a skipped operand. Missing/duplicate/cyclic/budget records fail closed.

`core/explanation-condition.mjs` parses only bounded boolean literals, identifier/
member labels, !, &&, || and groups. It reads copied booleans, never accesses the
labelled property or calls/evaluates application code. Calls, computed/optional
members, assignment and other syntax refuse. An unknown JS input is not assumed
boolean or coerced. Decisive short-circuit results retain unavailable dynamic
operands. Source literals are Code-linked constants, not observed reads. The
hold||true masking control distinguishes one copied read from one code constant;
changing one term is only a hypothetical logical conclusion, not an intervention.

The short explanation is about the recorded computation. The committed DOM
producer and current HTTP value ancestry are explicitly unestablished. Identifier
names do not become business meaning. Source/native action declarations use exact
current action context and still do not prove invocation; separate A05 bodies will
be integrated as independent facts in Task2. The same facts can serve simpler and
technical views, with details optional.

Existing v1 diagnostics omit dependency/target/occurrence links. Their passive
projection explicitly says historical/not reverified/current condition unavailable;
it does not reconstruct omitted records or alter the old report grammar.

The old provider serialised the entire fact object. An actual new privacy RED
shows this would expose new local details. `buildExplanationPrompt` now projects
only schema/property/boolean disabled/evidenceIds/fixed limits/allowed summaries.
Source labels, values, filenames, identity and richer condition/details never
enter the default prompt. Existing finite-sentence model behavior remains unchanged
for old facts and does not complete mandatory useful real-model L02.
