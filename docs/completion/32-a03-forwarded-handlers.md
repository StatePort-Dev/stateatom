## Source relationship and explicit limits

The selected native JSX callback can link through a private same-file function
component parameter to one explicit static JSX supply. Simple named/aliased
destructuring and `props.name` are supported, including a short wrapper chain.
The supplied lexical callback/useCallback/custom-hook resolver is reused. The
downstream binding, parameter declaration and supplied expression retain exact
ranges/digests and separate Code-linked evidence IDs. Anonymous supplied callbacks
have no invented function name and open their original expression range.

The visible entry reason says: Source declares this callback for the named prop;
transfer to this selected instance and runtime function identity were not observed.
That limit is present in the actual UI and original saved v1 export. Code-linked
declarations are not a parameter observation, committed callback, actual supplied
function identity, handler invocation or state/HTTP lineage.

Only an unescaped constant named/direct-function component and one bounded source
site qualify. Multiple sites remain unresolved even when they supply the same
callback. Exported/mutable/dynamic/wrapper-constructed components, prop writes/
receiver escapes, unsupported default/rest/computed/nested/duplicate parameters,
spread/duplicate/missing callback supplies and getter/factory leaves refuse.
Source props are not read or evaluated to choose a name.

A JSX element passed to clone/factory code, stored in a variable, or given to a
composite component as a child/prop is not treated as an untransformed supply.
This guard was added after a real intermediate control exposed a false Code-linked
clone result. Direct component returns/native JSX containers are the supported
source path, with16 ancestor steps,64 references/attributes and32 flat parameter properties;
existing resolution depth/cycle limits remain. Opaque transformations outside this
bounded source relation still lack a runtime transfer witness; the visible reason
preserves that gap. No whole-app caller/ownership argument is claimed.

Two instances from one source site may share only the declaration relation. Their
exact DOM/document/inspection identities remain separate. Two known source supplies
never borrow the nearest parent, equal callback name, timestamp or matching value.
