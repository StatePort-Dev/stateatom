# Editing flow and hierarchy correction

User direction: edit permissions only for production; novice-friendly direct purpose,
no technical configuration wall; preserve shared reference design and evidence semantics.
Prior autonomous execution preference applies; no extra approval round.

## Reproduction and cause

Saving a connection calls runtime invalidateScope and platform revoke, then UI only
loads the cleared state. Current selector is lost. Native reproduction retained under
/tmp/stateatom-editing-ux; first automation run lacked a trusted mouse gesture and is
not the reported failure. Second uses existing native production test click pattern.

## Bounded implementation

1. Local loopback dev defaults to supported native/response editing. Keep Chrome origin
   access and host limits; HTTPS remains production with existing scoped confirmation.
   Do not assume arbitrary HTTP/HTTPS sites are development. Ordinary attach needs no
   cache permission and does not clear data/reload. Explicit cache tooling remains advanced.
2. Saving settings on an attached page reconnects and refreshes the exact old native
   node/document; refuse replacement or tab/origin changes. Do not reuse old analysis.
   Production confirmation returns to the same selected element through the same guard.
3. Values lead; CSS selection and technical details leave the first viewport. Editing
   opens with Page fields by default, Draft + Apply by default. Live/source/refresh/reset
   remain accessible in Editing options. One shared editor, no duplicate state or lost draft.
4. Local stale/empty/disconnected states each get a useful next action; hide irrelevant
   production settings in dev. Progressive detail retains Unknown/Unsupported boundaries.
5. Regression tests for defaults, grants, replacement, settings transitions, editor
   drafts/live; native screenshots of actual flow and 360px keyboard/overflow. Check
   shared UI, full suite as needed. Update changelog/audit, scoped local commit, reopen demo.

## Evidence boundaries

Local automatic editing means canonical loopback or an explicitly configured development
origin. An unclassified remote site is never promoted by URL scheme or page claims.
App-side writes occur only on the user's edit/apply. Local undo does not undo server work;
keep this visible at editing time, full technical limits in Details.
