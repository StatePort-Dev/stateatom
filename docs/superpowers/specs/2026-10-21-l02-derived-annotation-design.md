# L02 next slice — derived annotation, technical proposal

2026-10-21; prepared against bee61ee / exact Atom .20261021.28.
Purpose: investigate useful optional local assistance without changing what evidence
establishes. This is a bounded design artifact, NOT implemented behavior, accepted
model quality, a new approved release scope or completion of L02. The approved
feature direction is completion/07 and12; the field names below are proposed
implementation choices. No Live/production-permission/handoff decision is made here.

## What the actual runs establish

.26 baseline24:20 strict accepted/4 safely rejected; .27 corpus30:30 strict accepted,
including6 incomplete/5 untrusted; every displayed result equals its template.
.28 fixes phase presentation and passes actual installed product controls. Prompt,
literal validator and schema are unchanged; the30-case campaign was not rerun .28.
The finite selector has demonstrated no added usefulness. More real inferences,
lower latency, successful JSON or another equivalent sentence cannot change that.

Goal for the next provider is a short, clearly DERIVED annotation that helps the
reader understand a supported result or its missing boundary. Existing deterministic
summary, original local details, exact references and limitations remain the source
of truth. Generated text never becomes Observed/Code-linked/Experimentally verified.
No generated action, permission, graph edge, causal join, source read or app call.

## Alternatives and selected direction for implementation

1. Keep the finite selector: safest baseline and retained control, but actual runs
   show no benefit. It stays experimental; it cannot discharge mandatory O01 alone.
2. Version a separate derived-annotation provider over an explicit abstract fact
   projection. This follows approved07; compare it with the same templates before
   prominence or acceptance. This is the proposed next bounded direction.
3. Send expressions, identifiers, arbitrary values, page text, HTTP payloads or source
   excerpts to obtain richer prose. Outside this change; no richer-input policy or
   consent is inferred from the existing model checkbox. No cloud/API key route.

Do not replace buildExplanationPrompt/validateExplanation or reinterpret old raw
outputs under a new schema. Keep the old provider and immutable receipts callable.
No provider swap in the product until the new source/provider is independently
exercised and its actual fixed-corpus factual/usefulness results are available.

## Proposed input projection: local-derived-facts/1

Only inspectionExplanationFacts output for the EXACT current snapshot is eligible.
Do not accept a page object/raw graph/source record as model input. Use a new pure
projection module and explicit own-data reads, without expression/getter execution,
coercion of unknowns or mutation/freezing of application objects. Copy, do not infer.

| Field | Origin / interpretation | Model inclusion |
| --- | --- | --- |
| schema, question, property, status | Version and closed internal enums | Explicit enum only |
| deterministicSummary | Existing fixed template, produced by code | Existing trusted string only |
| disabled | Existing copied boolean or null | Preserve null/unknown |
| condition.value | Existing pure copied-boolean model | Boolean/null; not committed DOM proof |
| condition.masking, hypothetical | Existing bounded model | Preserve hypothetical qualification |
| condition.knownTrueTerms / knownFalseTerms | Existing model counts, not app execution counts | Finite nonnegative integers or unavailable |
| condition.unknownInputs / observedInputs / literalInputs | Existing model counts with distinct status | Do not convert unavailable to false |
| observedBodies | Existing admitted independent body-entry count | Count only; no callback-object/effect claim |
| limitations | Existing deterministic fixed limitations | Exact copy, immutable |

Do NOT include condition.inputs/skipped arrays, labels, expressions, source spans,
filenames, source digests, paths, symbols, arbitrary property/scalar values, parsed
origin pointers/exchange IDs, comments, page/HTTP text, instance/tab/run identifiers
or freeform user questions. No business meaning is inferred from variable names.
A condition absent/stale/unavailable is unavailable, not a zero-blocker condition.
A body count without a binding remains a separate observation, not proof of callback
identity or downstream effect. Unsupported field shapes stay absent with a visible
boundary; never clamp a large/unknown count into a known small count.

An explicit source-level privacy review of EVERY projected field and positive/
negative injection tests precede any new model call. This expands only bounded
non-sensitive abstract facts allowed by07, not raw/richer application content. No
field becomes model input merely because it was added to local inspector details.
The old explicit seven-field projection remains unchanged for the original provider.

## Fact references and output: local-derived-annotation/1

The new projection assigns fixed internal fact tokens to the admitted input fields,
for example summary, condition-result, masking, unknown-input-count and body-count.
The model references only those supplied tokens. Tokens refer to exact projected
fields, not newly generated evidence graph edges. Keep original evidenceIds locally
as an immutable copied set for this SAME snapshot; do not send arbitrary application
IDs as instructions or create a fabricated per-clause causal link from proximity.
Original IDs and deterministic limits are added from the sealed local projection,
never repaired from incomplete or invented model output.

Proposed model result: schema marker, one short text annotation and a nonempty
subset of the supplied fact tokens. No action/code/permission/URL fields. Reject
extra properties, unknown/duplicate tokens, incorrect schema/types, empty/oversized
text and malformed JSON; retain the current4096-byte raw response bound. Any new
text-length/token limits must be declared before the first evaluation, not tuned
against failed examples to manufacture success. No invented acceptance percentage.

Structure and token checks do NOT prove natural-language entailment. Generated
prose may still be wrong despite valid JSON. Evaluation must reject incorrect or
unsupported factual/action claims, including a correct supplied reference attached
to an unsupported claim. Do not claim a runtime semantic validator exists merely
because IDs and lengths were checked. Keep deterministic limitations and nextAction
outside generated fields, displayed unchanged. Render generated text with textContent.

Stale/unavailable/historical facts keep deterministic responses; no free model
reconstruction of missing computation history. Cancellation, timeout, rejected
structure, API/device/policy failure and changed target/source/provider/options all
fall back to the deterministic result. New annotation is visibly derived and
experimental; no source status is upgraded. Retain the existing epoch/AbortSignal,
explicit Explain, opt-in, session destruction and bounded in-memory identity rules.
No persistent model cache or automatic per-selection inference is introduced.

## Fixed evaluation, before product exposure

Keep the existing30 cases, including all original24 facts, as the first fixed set;
keep the original corpus/version/receipts unchanged. Register new provider/projection/
output schema, full generated prompts, exact source/host hashes and evaluation rubric
BEFORE inference. If a missing product-relevant example is discovered, add a versioned
supplement and report it separately; never silently replace failed old cases.

For each real output compare with the deterministic template and retain:

- factual entailment: each clause mapped to the supplied projected fact, with an
  explicit supported/unsupported judgment; no binding→invocation, source→DOM,
  copied logical consequence→verified intervention, body→callback/effect or
  matching value→HTTP origin promotion;
- unknowns/limitations: skipped, unsupported, stale and missing ancestry preserved;
- concision: actual word/sentence count and whether another sentence adds useful
  meaning, rather than satisfying a new arbitrary length score;
- usefulness: a concrete improvement for the selected question beyond the already
  available template, or NONE with reason. Mere paraphrase and latency are NONE;
- actual availability/options/model result vs fallback, raw/validated output,
  cold/download/initialization versus warm timings, cleanup and exact candidate.

Agent evaluation may use the fixed facts and deterministic model as reference;
record the per-case reasoning, not a model's self-rated quality or number of passed
JSON schemas. An independent human is not a blocker. Keep the historical >=25 with
5incomplete/5untrusted and approved20–30 criteria; this30 set satisfies their counts.
No incorrect factual/action claim is acceptable in the evaluated acceptance corpus.
The approved requirement is demonstrable usefulness beyond templates: do not invent
an easier percentage threshold, or call no-benefit delivery complete.

A successful structural pass without benefit leaves mandatory L02 open. Failed
outputs remain in the denominator/raw history; no generic safety fallback is counted
as successful inference or usefulness. If this projection supplies too little
context for benefit, record that specific result and define a later bounded change;
do not silently add source/business/private fields or cloud models.

## Bounded implementation order and stopping points

1. NEXT ONLY: add pure versioned projection + structural annotation validator and
   privacy/identity tests. No model call, product selection, input-policy expansion,
   UI change, package prominence or L02 acceptance at this source-only checkpoint.
2. Add the separate opt-in provider/evaluation adapter with lifecycle tests; run the
   registered real30-case comparison on an immutable candidate and grade every case.
3. Only if factual/unknown/usefulness gates support it, expose the derived annotation
   in existing UI placement and verify exact installed opt-in/Cancel/stale/offline/
   fallback/narrow/keyboard controls. Source/package checks on that final candidate.
4. ONE whole-L02 scope/code/evidence review after all approved gates are met, then
   one correction pass. No per-probe reviewer loop or new independent-human blocker.

Design self-check: no new release scope, no richer private fields, no fabricated
entailment guarantee, no new acceptance thresholds, and no implementation/results
claimed here. Chosen names, bounds and presentation are explicit proposals for the
next task, not claims that a user already approved exact implementation details.
