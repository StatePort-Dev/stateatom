# Bounded React state handoff observation

The autonomous roadmap instruction authorizes this next mechanism experiment.
Primary/control remain unchanged React P2/P1. Preserve the original experiment,
fullPath:false and all historical denominators. No new framework or resolver.

The current observer knows parsed object identity and a committed host expression,
but not the state queue/update which actually returned that object. Observe pinned
React 18.3.1 original queues, update objects, reducer application and hook results
inside the existing digest/site-count guarded development vendor transform.
Return original hook arrays, setter functions, actions and values unchanged. No
extra getter, updater, Promise reaction, body read, user expression evaluation or
new scheduling. Keep this opt-in, requiring the host-props/source-consumption mode.

Observe mountState queue creation, dispatchSetState's actual new update, actual
updateReducer applied branch, the current-hook predecessor, and the exact returned
hook array. The source transform associates only statically identified React
useState calls with a lexical binding. A state read is accepted for a selected
host property only if its exact render Fiber is a committed ancestor of that host
and its native hook/state/queue identities still match. No component name, value,
latest-dispatch, URL or timing join. Cloned/rebased/unseen updates and functional
updater value ancestry stay Unknown; actual events can still be reported.

JSON consumption receives a bounded identity token. Direct object replacement
may link the processed update and returned state to that exact parsed object and
exchange. This is an object-handoff claim, NOT current field-value ancestry.
Unobserved raw/equal-value writes remain unknown. Never set fullPath true.

Bound queues/records and use weak identities; stop/navigation/source invalidation
must not return a current handoff. Default mode produces no new taps or source
wrappers. Preserve origin licenses and actual vendor input/output identities.

Checks: RED unit controls for opt-in config/site counts/source hook eligibility;
actual native unchanged P2/P1; two instances and queued replacements; same-value
replacement, functional updater, suspended/uncommitted render and late/missing
history; off/on setter identity, lazy initializer/updater/getter/error behavior.
Then expose the same scoped evidence through the existing panel/export/reader,
verify actual UI separately and repeat only affected regressions. Source review
must reject any asserted field origin from this identity-only mechanism.


Review controls require post-destructuring association using actual bound values,
not just the previously returned array. Own iterator/array mutation cannot join a
different object. Repeat hook-state identity checks at witness time to exclude
cached JSX from an earlier render phase. Finished-tree ancestry is traversed from
the actual committed root; a reciprocal branded Fiber alternate is eligible only
when it retains the exact same hook object/state identity (bailout). This is not
proof of a new public useState call or its ordinal. Limits and failures remain
explicit; old failing attempts are retained.
