## Supported source forms and exact boundaries

The normal development workflow uses the open project helper and open Vite plugin
(F03 setup). Basic needs neither. Ordinary instrumentation defaults to source
consumption without the opt-in experimental host-props/first-read adapters. The inspected
application, helper and source folder must refer to the same current project;
source access by itself adds no runtime observation. Actual native/IDE tests in
A01.1/2/4 use copied projects and manual contributor pairing, not a closed answer
launcher or a fabricated result table. The retained installed setup checks in F03
remain a distinct result, not a new installed-VSIX test in these increments.

| Form / mode | Useful supported result | Explicit boundary |
|---|---|---|
| One dynamic JSX child of a native host, primitive string/number, Text | Matching actual DOM marker/value, exact source digest/range and retained original read dependencies | Current read fragment, not proof of final DOM writer or upstream state/HTTP origin |
| Native HTML button with JSX disabled expression, Disabled | Original boolean/read/logical/unary nodes on the executed path | No arbitrary getter evaluation or forced skipped operand; checked/value are outside these two selected properties |
| Direct/local destructured binding and repeated render | Actual read/destructure IDs and observed values at that occurrence | Unknown root/parameter/mutable-binding history stays explicit; a value read is not a writer proof |
| Forward/Label wrapper and explicit spread override | Exact selected Label source/local parameter read, separate selected instance even with equal text | Parameter provenance not observed; no inferred edge from the original upstream prop, including equal-output override |
| Actual same-output/changed-output source edits | Stale old result, changed served module/source digest, new page/run on explicit inspection, exact current IDE bytes | Instrumented plugin uses a real watcher-triggered full reload; no claim of state-preserving framework Fast Refresh |
| React18.3.1 dev/classic opt-in final-host-props profile | Pinned immutable props/Fiber/DOM identity on tested forms with original reads | Separate experimental profile; clone/manual/mutable/replacement-freeze/spread/portal/hydration/custom witnesses refused; not React19 support |
| Multiple aggregate text expressions, literal-only/no recorded expression, excluded execution context or missing marker | Source/Basic information where available, otherwise explicit unsupported result | Do not manufacture a target/read from nearby names or equal DOM text |
| Source-linked/no instrumentation/other framework mode | Its recorded Basic/source fragments | No ordinary React runtime-read or committed-producer claim from source access/detection alone |

Identity fields have separate roles. sourceDigest binds the exact original source
bytes. Actual served module text in A01.1 records the changed compiled input; that
single decoded-text SHA is neither a whole app build hash nor an invocation ID.
Page/run and selected backend document/node delimit the observation generation.
The DOM marker/target scope identifies the recorded instrumented occurrence; target
and dependency node IDs/time identify original retained events. A later inspection
clock alone does not mean another execution. The independent19 and ordinary
synthetic19 cases have no established render-to-final-commit identity: it remains
Unknown/Unsupported rather than being filled from a same-value trace. The pinned18
adapter carries its own scoped host/props/root/commit identities under its tested
contract. Saved exports remain historical exact bytes through source/app changes.

JavaScript semantics controls remain behavioral: the current host/source-consumption
runs compare actual off/on outputs, getters, callback receivers/identities, thrown
objects, original unhandled Promise identities and suspension order. Generic
transform unit tests cover short-circuit, conditional, receiver, exact thrown
object, defaults, optional calls and mutable/loop history refusals. Synthetic
ordinary form logs separately show zero inspection-side getter calls. These checks
are scoped to the registered programs and versions, not a universal transform proof.
